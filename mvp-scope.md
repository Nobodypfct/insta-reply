# Insta-Reply — MVP Scope

## Идея одной строкой
Автоответ на комментарии в Instagram + автоматическая отправка DM, с продвижением через партнёрскую сеть блогеров (revenue share).

---

## Фаза 0 — "Ручной MVP" (делаем ПЕРЕД тем, как кодить личный кабинет)

Цель: проверить, что люди вообще готовы платить, прежде чем строить self-serve инфраструктуру.

- [x] Технический бэкенд работает (webhook → reply + DM) — готово
- [ ] Найти 5-10 реальных платящих клиентов вручную:
  - ты сам подключаешь их аккаунт через meta developers (получаешь токен, вставляешь в конфиг)
  - шаблоны фраз меняешь вручную в коде/базе по запросу клиента
  - оплату принимаешь вручную (перевод на карту / вручную через ЮKassa-ссылку)
  - партнёрские выплаты считаешь в Google Sheets
- [ ] Цель: подтвердить, что 5-10 человек реально платят и остаются на 2-й месяц

**Если это не подтвердится — не имеет смысла строить всё, что ниже.**

## Фаза 1 — Self-serve MVP (после подтверждения спроса)

### 1.核心 функционал (Core product)
- Подключение Instagram-аккаунта (OAuth через Facebook/Instagram Login)
- Возможность подключить **несколько** Instagram-аккаунтов на один личный кабинет (для SMM/продюсеров, ведущих клиентские аккаунты)
- Выбор конкретного поста/рилса ИЛИ применение правила "на все посты"
- Шаблоны:
  - шаблон ответа на комментарий (1 или несколько фраз, рандомный выбор)
  - шаблон текста для DM
- Вкл/выкл автоматизации по каждому подключённому аккаунту
- Базовая статистика: сколько комментариев обработано, сколько DM отправлено

### 2. Лендинг
- Объяснение продукта в 1 экран: что делает, для кого, сколько стоит
- Явный CTA на регистрацию / подключение
- Раздел "как это работает" (3-4 шага)
- Ссылка на партнёрскую программу (для блогеров, которые захотят стать партнёрами)

### 3. Личный кабинет (для клиента-владельца аккаунта)
- Регистрация / вход
- Список подключённых Instagram-аккаунтов (+ кнопка "подключить ещё один")
- Настройки шаблонов на каждый аккаунт
- Статистика по каждому аккаунту
- Раздел "Настройки аккаунта":
  - управление подпиской (тариф, дата продления, отмена)
  - способ оплаты
  - смена email/пароля

### 4. Партнёрский кабинет (Affiliate)
- Уникальная реферальная ссылка / промокод
- Статистика: переходы → регистрации → платящие клиенты
- Расчёт начисленной комиссии (нарастающим итогом)
- Заявка на выплату (форма: сумма, реквизиты)
- История выплат

### 5. Юридическое
- Политика конфиденциальности (есть, RU + EN версии)
- Пользовательское соглашение / оферта (нет, нужно сделать)
- Договор оферты для партнёрской программы (условия revenue share, сроки выплат) (нет, нужно сделать)

## Технический стек (черновой)

| Слой | Выбор | Комментарий |
|---|---|---|
| Backend | Node.js / Express | уже есть, работает |
| БД | Supabase (Postgres) | free tier, + встроенный Auth |
| Auth (личный кабинет) | Supabase Auth | не нужно поднимать отдельно |
| Hosting backend | Render / Railway | Render free tier ограничен (sleep), взвесить платный при росте |
| Frontend (кабинет) | пока не выбрано | можно начать с простого React/Next или даже no-code (напр. Retool-подобные для внутреннего MVP) |
| Платежи RU | CloudPayments / Tinkoff | под рекуррентные подписки |
| Платежи US (позже) | Stripe | если пойдём на англоязычный рынок |

---

## Что осознанно НЕ делаем в MVP (backlog на потом)
- Мультиязычный интерфейс кабинета
- Аналитика уровня "conversion funnel" внутри кабинета
- Поддержка других платформ (VK, Telegram-комментарии)
- Автоматический скрапинг/поиск блогеров
- Сложные триггеры (по ключевым словам в комментарии) — можно добавить быстро, но не в v1
- Очереди (Redis/BullMQ) — пока нагрузка низкая, in-memory/простая обработка ок
