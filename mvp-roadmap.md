# Insta-Reply — Roadmap MVP

Порядок категорий = примерный порядок разработки (сверху вниз), т.к. каждая следующая зависит от предыдущей.

---

## 1. Backend / Infrastructure (фундамент — делаем первым)

- [ ] Завести проект в Supabase (БД + Auth)
- [ ] Спроектировать и создать таблицы:
  - `users` (владелец кабинета)
  - `ig_accounts` (подключённые Instagram-аккаунты, много на одного user)
  - `reply_templates` (шаблоны ответа на комментарий, привязаны к ig_account)
  - `dm_settings` (текст DM, привязан к ig_account)
  - `activity_log` (лог обработанных комментариев — для статистики)
  - `subscriptions` (тариф, статус, дата продления — привязано к user)
  - `affiliate_links` (реф. код/ссылка, привязано к user-партнёру)
  - `affiliate_referrals` (кто кого привёл, статус, начисленная комиссия)
- [ ] Переписать текущий `server.js`/`store.js` под мультитенантность (сейчас — под одного юзера, нужно — под многих)
- [ ] Токены шифровать перед сохранением в БД (не хранить в открытом виде)
- [ ] Механизм обновления Instagram access token (токены "протухают", нужен авто-рефреш или напоминание)
- [ ] API-эндпоинты для фронтенда:
  - CRUD подключённых ig-аккаунтов
  - CRUD шаблонов
  - получение статистики
  - партнёрская статистика (переходы/рефералы/начисления)
- [ ] Хостинг backend — определиться: остаться на Render (учесть free tier sleep) или перейти на платный план / другой провайдер

## 2. Auth (вход в кабинет)

- [ ] Регистрация / логин через Supabase Auth (email+пароль, можно добавить Google-логин позже)
- [ ] Восстановление пароля
- [ ] Отдельный OAuth-флоу для ПОДКЛЮЧЕНИЯ Instagram-аккаунта клиента (это не логин в кабинет, а отдельное разрешение на доступ к их IG) — самый технически сложный кусок, тестировали ранее руками через meta developers, теперь нужно встроить в UI

## 3. Frontend / Личный кабинет

- [ ] Выбор стека (React/Next.js — рекомендация по умолчанию, можно поменять)
- [ ] Страница логина/регистрации
- [ ] Dashboard — список подключённых Instagram-аккаунтов
- [ ] Кнопка "Подключить новый Instagram-аккаунт" → OAuth-флоу
- [ ] Страница настроек аккаунта (одного ig_account):
  - вкл/выкл автоматизации
  - редактирование шаблонов ответа на комментарий
  - редактирование текста DM
  - выбор: "на все посты" / "на конкретный пост"
- [ ] Страница статистики (обработано комментариев / отправлено DM, по каждому ig_account)
- [ ] Страница "Настройки аккаунта" (общие):
  - смена email/пароля
  - управление подпиской (тариф/статус/отмена)
  - способ оплаты
- [ ] Страница партнёрского кабинета:
  - реферальная ссылка/промокод (генерация + копирование)
  - статистика: переходы → регистрации → платящие
  - расчёт накопленной комиссии
  - форма заявки на выплату
  - история выплат

## 4. Design / UI

- [ ] Определиться со стилем (минималистичный/техничный vs дружелюбный — обсуждали в самом начале нейминга)
- [ ] Дизайн-система по-минимуму: цвета, типографика, компоненты (кнопки, поля ввода, карточки)
- [ ] Макеты ключевых экранов: логин, dashboard, настройки аккаунта, партнёрка (можно сразу в коде через frontend-design подход, без отдельного Figma-этапа, если хочешь сэкономить время)
- [ ] Лого / минимальный брендинг

## 5. Лендинг (marketing site, отдельно от кабинета)

- [ ] Структура: hero (что делает продукт) → как работает (3-4 шага) → тарифы → CTA на регистрацию
- [ ] Отдельный блок/страница "Партнёрам" — питч для блогеров с объяснением revenue share
- [ ] Домен (instareply.ru — уже выбрали, нужно купить)
- [ ] Хостинг лендинга (может быть тот же Vercel/Netlify — легче, чем сам backend, т.к. это просто статика)

## 6. Payments

- [ ] Выбрать провайдера RU (CloudPayments или Tinkoff — рекомендация из-за поддержки рекуррентных подписок)
- [ ] Оформить ИП (обязательно для легального приёма регулярных платежей — сделать ДО подключения платёжки)
- [ ] Интеграция подписки (создание/отмена/продление) в биллинге провайдера
- [ ] Обработка webhook от платёжки (успешный платёж → активация подписки в своей БД)
- [ ] (Позже, для US-рынка) Stripe — отдельная задача, требует юрлица в США или посредника (Paddle/LemonSqueezy)

## 7. Legal

- [ ] Политика конфиденциальности — готово (RU + EN версии есть)
- [ ] Пользовательское соглашение / публичная оферта на подписку
- [ ] Оферта для партнёрской программы (условия revenue share: %, сроки выплат, минимальная сумма к выводу, что считается "приведённым клиентом")
- [ ] Если будет юрлицо — реквизиты во всех документах

## 8. Meta / Instagram compliance

- [x] Приложение переведено в Published/Live
- [ ] Пройти полноценный App Review (Advanced Access на `instagram_business_manage_comments`, `instagram_business_manage_messages`) — обязательно для работы с аккаунтами клиентов, которые не являются тестерами
- [ ] Подготовить скринкаст для App Review (весь флоу: подключение → коммент → автоответ → DM → кабинет)
- [ ] Business Verification в Meta (может понадобиться для Advanced Access)

## 9. QA / тестирование перед запуском

- [ ] Протестировать полный флоу на 2-3 реальных аккаунтах (не только etot_chuvak/viva_la_kolya)
- [ ] Проверить защиту от reply-петли (уже пофикшено, но перепроверить после переезда на мультитенантность)
- [ ] Проверить обработку истёкшего/невалидного токена (что видит юзер в кабинете)
- [ ] Нагрузочно не тестировать — на этой стадии не нужно

## 10. Go-to-market (параллельно с разработкой, не после)

- [ ] Список первых 20-30 потенциальных блогеров-партнёров для холодного питча
- [ ] Шаблоны питча (короткий + полный — уже готовы из прошлых обсуждений)
- [ ] Начинать питчить можно уже на этапе, когда core-функционал + базовый кабинет готовы, не дожидаясь партнёрского кабинета в 100% готовности

## Приоритеты, если времени не хватает на всё сразу

**Критично для первого запуска (must have):**
Backend + Auth + core Frontend (dashboard, подключение аккаунта, шаблоны, статистика) + Legal (оферта) + Payments

**Можно сделать чуть позже, без блокировки запуска:**
Полноценный дизайн (можно стартовать с простого UI), партнёрский кабинет (первое время можно вести вручную в Google Sheets, автоматизировать после первых 10-15 партнёров), лендинг (можно временно заменить одностраничником)

**Точно не первая волна:**
Stripe/US-рынок, полный App Review Advanced Access (можно работать с ограниченным числом тестеров, пока не пройдёшь ревью)
